# V0.3 验证记录

日期：2026-10-15。

## 实现范围

- FrameExtractor：按 CFR 帧序号定位，校验范围和解码器报告的位置，返回原始帧。
- ReviewWorker：后台独立解码，仅保留最新待处理请求，使用请求序号过滤过期结果；关闭后释放句柄。
- ReviewDialog：异常起点截图、前两秒定位、滑块定位、上一帧/下一帧、静音播放/暂停、原分辨率 PNG 导出。
- 主窗口：双击异常行或点击复核按钮打开模态复核窗口；关闭、Esc、父窗口关闭均等待解码退出。

## 1080p 实际编码样本

执行：

```powershell

```

结果：60 秒视频，1800 帧，两段黑屏与两段冻结。选择第二条事件后定位到 25.000 秒，即索引 750（界面显示第 751 帧），导出 PNG 为 **1920×1080**。导出文件为本地 `screenshots/v03-freeze-25s.png`，不纳入 Git。

主窗口和复核窗口截图保存为 `images/v03-analysis.png`、`images/v03-review.png`，已目视检查中文文字、图像比例、时间位置和操作按钮。截图通过 Qt 离屏平台生成，不是原生 Windows 桌面点击验收；本轮未验证系统文件对话框交互。

## 已知限制与后续

- CFR 定位，VFR 暂不保证精确；编码器不支持定位或返回不符帧号时明确报错。
- 静音播放，无音频；慢解码时跳过部分显示帧以跟随时间，不用于评估源视频丢帧。
- 关闭等待当前原生解码调用返回，不能强行中断长期阻塞的解码器。
- 截图按用户选择手动保存，不自动批量导出、不持久化截图与异常关联。
- 仍采用合成但真实编码的验证素材；真实会议视频泛化评估待补充。
- 下一步 V0.4：SQLite 数据存储，保存任务、异常和截图关联。
