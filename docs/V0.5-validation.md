# V0.5 项目与任务管理验证

日期：2026-10-15。

## 交付范围

- 项目创建、重命名；项目名称去除首尾空白，限制 1–80 字符，防止同名项目。
- 分析前选择项目和填写任务名称；留空沿用文件名，任务名上限 120 字符。
- 历史任务重命名、在项目之间移动、移回未分组。
- 按项目和任务名/文件名组合筛选，字面子串搜索；切换筛选重置到第一页。
- CLI 保存支持 `--task-name` 和已有 `--project-id`，要求同时提供 `--database`。
- SQLite 结构版本 1 → 2 自动迁移：新增 projects、任务 title/project_id 与索引。旧任务仍保留原 ID、异常、配置和截图关联，默认归入未分组。

## 数据安全与迁移验证

测试以 V0.4 的三表结构构造版本 1 数据库，包含原始 Metadata、算法配置、异常与截图记录，升级后逐项检查；再次连接不会重复迁移。

模拟迁移在执行 ALTER TABLE、建立索引和更新版本之后失败，验证事务回滚后仍是版本 1，任务没有新增字段，projects 表未残留，原截图记录仍存在。

其他覆盖包括同名/空白/过长名称、无效项目 ID、无效任务 ID、字面 `%`/`_` 搜索、组合筛选和分页、移动后截图关联不变、保存失败不留下半条任务。

## 界面及编码样本验证

GUI 测试覆盖开始分析前项目和名称选择、分析中禁止修改、历史恢复、项目/任务重命名、任务移动、搜索后页码归零、新建项目与重复名称提示。CLI 子进程验证任务名/项目归属持久化和缺少数据库参数时的错误返回。

运行 60 秒、1080p、30 FPS 的实际编码合成样本，以“会议室投屏验收”项目、“1080p 黑屏与冻结回归”任务保存。分析 1800 帧，检出 2 段黑屏和 2 段冻结；在 25 秒定位索引 750，保存 1920×1080 PNG。重新连接数据库后，项目 ID、任务名、四个异常及截图关联均保持一致。

复现命令：

```powershell
.venv\Scripts\python tools/render_gui_validation.py "samples/最终验收 1080p.mp4" --database data/v05-validation.sqlite3
```

默认验证数据库 `data/gui-validation.sqlite3` 中的旧 V0.4 记录也已实际升级。`docs/images/v05-analysis.png`、`v05-history.png` 和 `v05-review.png` 为 Qt 离屏渲染，已目视检查主窗口四条事件、任务名称、项目和历史筛选控件。本轮不声称完成 Windows 原生输入对话框的人工验收。

## 退出清理验证

开发中曾出现全部断言通过但进程退出时 Qt 原生崩溃。调整测试夹具：整个会话保留一个 QApplication，每个 GUI 测试后关闭窗口、等待工作线程退出、销毁窗口并处理延迟删除，再释放 Python 引用。22 项 GUI 专项已正常退出（退出码 0）。最终完整回归结果另列于下方。

## 当前边界

- 项目是逻辑分组，不移动视频/截图文件，不提供删除、归档、批量管理或用户权限。
- 项目名按 SQLite NOCASE 判重，英文大小写不敏感；未实现完整 Unicode 大小写折叠。
- 迁移不自动生成备份；升级前可关闭程序并复制数据库。版本 2 不能由旧 V0.4 打开，需要回退时恢复原备份。
- 旧版任务名沿用完整文件名；新任务默认名称最多取文件名前 120 字符。
- 保留已有 CFR、静音复核、源文件一致性和截图路径依赖等限制。
