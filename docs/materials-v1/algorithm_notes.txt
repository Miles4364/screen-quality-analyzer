智能会议设备投屏质量分析系统 V1.0
算法与参数核对记录
核对依据：core/video_reader.py、core/analysis_engine.py、core/black_detector.py、core/freeze_detector.py、core/quality_score.py、core/models.py。
核对日期：2026-10-20

公式一：帧时间与实际分析时长
t_k = k / f，T = N / f
其中，k 为从 0 开始的帧索引，f 为 VideoReader 从解码器取得的有效帧率，N 为实际成功读取的总帧数，t_k 与 T 的单位为秒。事件使用左闭右开区间 [start_time, end_time)，末尾的 T 包含最后一帧的显示时长。此实现面向固定帧率视频，未按每帧 PTS 实现变帧率精确定位。不得将 Metadata 中的容器时长直接等同于实际分析时长。

公式二：黑屏候选帧的平均亮度
B_k = (1 / M) × Σ G_k(p)
其中，G_k(p) 为第 k 帧缩放后第 p 个像素的灰度值，M = 320 × 180 = 57600。默认将图像缩放为 320×180，再调用 COLOR_BGR2GRAY 转换。B_k < 10.0 时该帧属于黑屏候选。候选帧连续持续时间达到 0.5 秒才输出 BLACK_SCREEN 事件。事件的 average_brightness 为候选帧平均亮度的算术平均值。这里检测的是整帧低亮度，暗场画面也可能触发，需结合原视频复核。

公式三：疑似冻结的变化像素比例
R_k = (1 / M) × Σ 1(|G_k(p) − G_(k−1)(p)| > 5)
其中，1(条件) 在条件成立时取 1，否则取 0，M 同上。源码使用 cv2.absdiff 后比较阈值，再对布尔矩阵调用 numpy.mean。R_k < 0.01 时视为相邻帧变化不足，连续时间达到 0.5 秒才输出 FREEZE 事件。第一对相似帧的候选开始时间取前一帧时间。黑屏候选帧会切断冻结候选并清空前一帧，即使该段黑屏未达到输出事件的持续阈值，也不会跨越它合并冻结。静态 PPT 或低运动画面与冻结可能相似，因此输出名称保留“疑似冻结”。

公式四：时长占比质量评分
S = round(clamp(100 − 100 × B / T − 50 × F / T, 0, 100), 2)
其中，T 为实际分析秒数，B 为裁剪到 [0,T] 后黑屏事件区间并集的时长，F 为同范围内冻结区间并集扣除与黑屏重叠部分后的时长。clamp 表示限制到 0 至 100，round 表示保留两位小数。黑屏扣分为 100×B/T，疑似冻结扣分为 50×F/T。规则版本为 duration-v1，属于本项目自定义指标，并非行业认证指标。无有效时长或帧数、异常时间无效、存在不支持的异常类型时，不输出有效分数。现有人工复核状态用于记录与筛选，不改变自动检测事件或这项评分。

严重等级：
两个检测器均按事件持续时间划分。不足 1 秒为 LOW，达到 1 秒且不足 2 秒为 MEDIUM，达到 2 秒为 HIGH。输出门槛由各检测器的持续时间阈值决定。默认 0.5 秒以下不输出事件。时间边界比较使用 1e-9 容差以减轻浮点运算误差。

默认配置：
black_threshold = 10.0
black_duration = 0.5 秒
freeze_pixel_threshold = 5.0
freeze_change_ratio = 0.01
freeze_duration = 0.5 秒
黑屏检测器尺寸默认 320×180，冻结检测器当前固定使用 320×180。

帧数误差处理：
当前实现不会简单忽略所有提前结束。仅在已读取帧数大于 0、缺帧数不超过 min(10,max(2,ceil(fps×0.1))) 且缺帧比例不超过 0.001 时，调用 FFprobe -count_frames 做独立核验。只有核验无解码错误且结果等于已读取帧数，才允许按实际读取结果结束。明显截断、核验失败、超时和取消不会当作成功。默认核验超时为 180 秒。未知总帧数时仍无法保证识别所有提前截断。

验证数据口径：
tools/generate_samples.py 默认生成 60 秒、30 fps 的确定性合成动态测试图，含黑屏 [10,12)、[40,41) 与冻结 [25,27)、[50,53)。编码后由实际解码链路读取和分析。默认样本预期黑屏共 3 秒、疑似冻结共 5 秒，自定义评分为 90.83。这里是具有已知注入片段的合成验证，不能据此宣称真实会议场景准确率、召回率或误报率。实际文档示例须使用本次验证输出，而不是只引用预期值。
