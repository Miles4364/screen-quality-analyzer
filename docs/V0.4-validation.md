# V0.4 SQLite 与历史记录验证

日期：2026-10-15。

## 功能范围

- 标准库 SQLite，结构版本 1；tasks、issues、screenshots 三张表，外键关联。
- 保存视频 Metadata、算法配置、分析统计、异常明细、保存时间、软件版本和源文件修改时间。
- 成功分析自动入库，保存失败保留当前结果并支持重试；取消/失败不产生成功记录。
- 每页 50 条历史记录，恢复结果不重新分析、不重复保存任务。
- 截图关联到任务与异常，保存路径、帧索引、时间和 SHA-256；支持浏览已保存截图。
- 源文件缺失/变化时禁止视频复核，仍可查看结果和截图；截图被覆盖或丢失时明确提示。
- CLI 可选 `--database`，JSON 返回 task_id，自定义阈值一并保存。

## 验证结果

最终完整回归：`python -m pytest -q` → **102 passed in 50.21s**，无跳过，进程退出码 **0**。

早期运行出现“断言全部通过但退出码为 1”，统一测试会话的 QApplication 生命周期并清理窗口后，最终完整回归正常退出。生产 GUI 仍只有一个 QApplication。

新增覆盖：

- SQLite 保存/关闭/重新连接后的模型与配置完全一致。
- 多条异常写入中途序列化失败，整个事务回滚，任务与异常均无残留。
- 外键校验、相同关联路径更新、不存在截图拒绝关联。
- 数据库锁定、无效路径、损坏数据库、未知版本、无版本数据库的保护。
- 分页顺序、找不到任务、源视频更改或删除。
- CLI 新进程持久化、自定义配置、保存失败退出码。
- GUI 自动保存、重试不重复、打开历史、缺失源文件禁止复核。
- PNG 保存与具体异常关联，重新连接后读取；截图被覆盖时阻止误展示。
- 截图写入成功但关联失败时保留 PNG 并明确报告错误。

## 存储与限制

- 默认数据库位置：仓库目录 `data/analysis.sqlite3`；可用 `--database` 自定义。
- 数据库和业务截图不纳入 Git。只记录媒体路径，不复制媒体文件。
- 每个操作独立连接，事务和外键检查，锁等待上限 0.25 秒；繁忙时报告错误并允许用户重试。
- 仅支持当前结构版本，不自动升级或覆盖其他数据库；未来迁移需要单独实现。
- 源视频一致性比较文件大小与修改时间；不能识别刻意保持这两者不变的内容替换。截图使用完整 SHA-256 校验。
- 没有任务分类、重命名、删除、视频重定位和数据库备份按钮。下一阶段 V0.5 继续项目/任务管理。
- 保留 V0.3 的 CFR、静音播放及原生解码调用不能强制中断等限制。
