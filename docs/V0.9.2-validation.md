# V0.9.2 视频末尾帧数偏差修复

日期：2026-10-16。

## 故障与证据

用户报告大视频分析失败，截图显示“视频提前结束：已读取 5637/5639 帧”。读取用户本地同一文件验证：文件大小 406,677,292 字节，24 FPS；视频流没有提供 nb_frames。OpenCV 报告 5639 帧，而 FFprobe 完整解码得到 nb_read_frames=5637，退出码 0，无错误输出。

因此，本例是把预估帧数当作精确计数所造成的误判，不是发现了文件大小上限。原视频未修改，也未上传 GitHub。

## 修复行为

小幅末尾差异才触发独立解码核验：缺帧绝对值不超过 min(10, max(2, ceil(FPS×0.1)))，且比例不超过 0.1%。FFprobe 的成功计数必须与 OpenCV 已读取帧数完全相同，且 stderr 无错误，否则仍失败。零帧、明显截断和解码异常仍保留失败行为。

核验最大 180 秒，每 0.2 秒检查取消；取消或超时会终止子进程并回收资源。界面显示核验状态，不将核验中的数据当作完成结果。

成功后按实际帧数收尾检测和计算时长。GUI、CLI JSON warnings、Excel 读取提示及历史恢复均显示元数据与实际计数差异；不修改原始视频，不改变数据库结构。错误页面不再一概建议检查 FFprobe 安装，而是引导查看具体原因。

## 验证

- 全量 pytest：167 passed，62.61 秒，无跳过，退出码 0。
- 新增计数一致/不一致、明显截断、FFprobe 错误输出、非法响应、取消、超时、子进程回收及历史提示恢复测试。
- 原问题视频源码端成功：5637 帧，实际分析时长 234.875 秒，15 段黑屏、1 段疑似冻结；生成 JSON 和 Excel，保留两帧差异提示。检测事件仍需人工复核。
- Windows 便携包保留内置 FFprobe，包名 ScreenQualityAnalyzer-V0.9.2-Windows-x64.zip。
- 使用打包版同一入口的 Qt 自检在原问题视频上完成后台分析、入库、历史恢复、人工复核和报告导出，退出码 0；GUI 截图与 Excel 回读确认 5637 帧及差异提示。测试中的人工确认标记仅用于验证流程，不作为视频内容结论。

## 使用边界

并非无条件忽略缺帧。核验会增加一次完整视频解码，耗时与视频编码和长度有关；超过 180 秒仍按未确认完整性处理。两种解码器计数相同也不能保证发现所有潜在损坏。固定帧率定位和疑似冻结误报边界保持不变。
